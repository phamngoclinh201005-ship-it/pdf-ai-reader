# Guest and account storage

- Get Started opens `/reader` without requiring an account. Guest PDFs, chat and AI results stay in component memory. Reloading, leaving the reader, or closing the tab discards them; no library API, browser database or PDF localStorage is used.
- Log in opens the authenticated workspace. Opening a valid PDF uploads it to the account's private library. Reading page/zoom, chat and AI actions autosave; the footer shows pending/saved state and failures are visible with Sync available to retry.
- `/workspace` reopens the most recently saved PDF; `/workspace?document=ID` opens a chosen library item. My Library supports reading again and deleting a document with its history. Logging out clears the reader.
- Storage uses MongoDB collections `library_documents` and `library_chunks`. PDF chunks stay under the BSON document size limit. Files can be at most 40 MB; a library can contain up to 100 documents and 200 MB. Reading-state payloads have bounded history lengths and size.
- Every list/read/download/update/delete is scoped to the authenticated session's user ID. Guests receive 401, another user's ID receives 404. Mutation requests retain the application's origin checks. Private GET responses use `Cache-Control: no-store`.
- Auth and library endpoints pass through Nuxt's same-origin proxy so cookies work on the separate Render domains and during SSR. Keep `NUXT_PUBLIC_API_BASE` unset and set `NUXT_BACKEND_API_BASE=https://paperflow-api-reif.onrender.com` on the FE. BE uses `Frontend__Origin=https://pdf-ai-reader-qpi8.onrender.com`.
- Redeploy both services after adding this module. Keep MongoDB credentials in Render environment variables; local .NET User Secrets are not deployed. Local dev can use `NUXT_BACKEND_API_BASE=http://localhost:5050` with `npm run dev:backend:local`.

Validation: `dotnet build backend/PaperFlow.Library.Tests --output .verification/library-tests`, then `dotnet .verification/library-tests/PaperFlow.Library.Tests.dll`. The tests create a temporary database and remove only that database, using no real email/AI calls. The browser harness `.verification/browser/check-library.mjs` additionally verifies guest reload loss, member persistence and cross-account isolation through the actual API and proxy.
